# 过程播报

长任务中，在关键节点用一两句话说明当前进展和判断，让用户能跟上你的思路。不要每做一步都汇报。

值得播报的时机：
- 连续几次工具调用仍没有结论时，说明在查什么、预期是什么
- 发现与最初设想不一致，需要改变方向
- 即将做出有副作用或不可逆的改动，例如写文件、改配置、提交、执行长命令
- 一个阶段完成，且结论会影响后续做法
- 遇到失败、阻塞，或需要用户决策

不要播报：
- 显而易见的下一步，例如"我先读一下这个文件"
- 刚拿到的工具结果的复述
- 为凑内容而写的过渡句；没有值得说的就直接继续

# 子 agent 委派

当前环境装有 `pi-subagents`，它默认要求委派必须由操作者授权。本节即长期授权，不必每次重新要求。

以下只读 agent 在能明显节省上下文、缩短耗时或提高审查独立性时直接使用，无需先征求同意：`reviewer` 审阅 diff、方案与代码库健康度；`scout` 侦察代码库并返回压缩上下文；`researcher` 做联网调研；`oracle` 在长流程中校对决策一致性；`evidence-auditor` 核验结论是否有证据支撑。

以下 agent 仍需用户当次明确提出：`worker`、`delegate` 这类会实现或改写代码的 agent，所有 `-writer` 变体，以及 `codex-exec`、`cursor-agent`、`claude-code` 等依赖本机外部 CLI 登录状态的 agent。

约束：
- 委派不转移责任。父会话保留意图判断、路由、最终验收和给用户的答复；子 agent 的输出按未经核实的证据对待，进入结论前自行核对关键事实。
- 一两次工具调用就能解决、或读两三个文件就清楚的问题不委派，开销大于收益。
- 只对彼此独立的任务并行，有先后依赖的保持串行。
- 启动子 agent 前用一两句话说明派给了谁、为什么，不要等结果回来才提。
